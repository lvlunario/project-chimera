## 0–5 minutes — Outcome and current demo

Chimera's intended operator is an integration or test engineer who needs to turn a
communications test run into reviewable evidence. Instead of handing off screenshots,
the operator will preserve the input identity, selected requirements, procedure version,
outcomes and report so another engineer can reproduce the reasoning.

Current runnable slice from a trusted checkout on Python 3.11+:

```bash
python -m chimera.cli run examples/workflow.json --evidence /tmp/chimera-review.json
echo $?
python -c 'from pathlib import Path; from chimera import RunEvidence; print(RunEvidence.from_json(Path("/tmp/chimera-review.json").read_text()).to_dict()["tasks"])'
```

Expected summary: health and ingest succeed, the synthetic link check fails, report is
blocked, evidence is saved, and the command exits 1. Use a new evidence path if the file
already exists. [Example declaration](../../examples/workflow.json) ·
[CLI manual](../MANUAL.md#declarative-workflow-cli) ·
[daily verification evidence](../daily/2026-09-13.md).

This demo proves dependency behavior, CLI validation and completed-run evidence. It does
**not** yet parse telemetry CSV, calculate link margin, evaluate a requirement verdict,
persist an interrupted run or generate the final report. Its failure is explicitly
synthetic rather than a measured communications result.

## 5–15 minutes — Concept: procedure state is not requirement verdict

Consider a requirement: **COM-LINK-001 — measured link margin shall be at least 3 dB**.
The future check can execute correctly, calculate 2 dB and return a **FAIL verdict**.
That is not a software execution error. Conversely, if the input unit is missing, the
check cannot make a defensible comparison; the outcome is **ERROR**, not FAIL and never
PASS. If ingestion failed first, dependent checks are **NOT EVALUATED / blocked**.

| Layer | Question | Example outcome |
|---|---|---|
| Workflow task | Did this step execute? | succeeded / failed / blocked |
| Requirement check | What does valid evidence show? | pass / fail / not evaluated / error |
| Evidence record | Can another engineer inspect the basis? | complete / missing / invalid |

Today Chimera implements only the first layer and completed-run snapshot mechanics.
The next core increment separates the second layer instead of treating every requirement
failure as an exception. This prevents a dangerous report where “software ran” is
misread as “requirement passed,” or bad input is misreported as a genuine threshold miss.

Proposed communications-link sequence:

1. Validate CSV columns, timestamp format and declared units.
2. Identify the exact input with a content hash; preserve the procedure/config version.
3. Calculate link margin from valid samples using a deterministic rule.
4. Evaluate COM-LINK-001 and retain failing samples plus threshold.
5. Mark dependent report content unavailable when prerequisite evidence is invalid.
6. Save/reopen the run and export matching JSON/HTML evidence.

### D-003 — Operator journey priority

Question: Which use case should define the first end-to-end acceptance path?

1. Investigate a failed link-margin requirement and hand off its evidence.
2. Diagnose malformed or missing telemetry without a false pass.
3. Reopen a passing run and reproduce its report.

Recommendation: **Prioritize 1**, then require 2 as the critical negative path and 3 as
the completion control. This centers the product on explaining failure while still
proving invalid data cannot silently pass.
