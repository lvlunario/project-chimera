## Setup and 20–30 minute walkthrough

Prerequisites: trusted checkout of the packet commit on Linux, Python 3.11 or 3.12;
prepared build tools for the maintainer install check. From the repository root:

```bash
python -m unittest discover -s tests -v
scripts/verify_clean_install.sh
python -m examples.approval_demo
python -m examples.verdict_demo
```

The install verifier creates/removes isolated temporary build/install environments.
It needs the build backend already available; no package is published. The approval
demo uses temporary synthetic JSON files and the CLI's Python entry function, not a
live radio or installed shell command. Installed entry points are verified separately
by the clean-install script. Temporary artifacts are removed even after an exception.

Before execution, predict the six `PASS:` controls:

1. True check: execution exit 0 and selected requirement pass.
2. Raised synthetic fault: exit 1; check failed, handoff blocked, health succeeded;
   completed evidence preserved.
3. Attempt the same evidence path: exit 3; original bytes unchanged.
4. Missing graph dependency: exit 2; no completed evidence file.
5. False check: execution exit 0, requirement fail, handoff succeeded.
6. Reload both run and binding JSON: identical assessment and binding digest without
   another CLI execution. The existing no-rerun test also counts task invocations.

Final line: `P1 walkthrough controls passed; temporary artifacts removed; PM acceptance pending`.
The verdict demo additionally shows error, blocked/missing not_evaluated, and all_passed
False. New run IDs/timestamps differ; engineering classifications must not.
