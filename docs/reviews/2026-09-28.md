## 6–15 minutes — Concept: agreement before presentation

A verification screen is dangerous if it can make inconsistent records look authoritative.
Chimera therefore treats a completed run like a controlled test package, not a loose folder
of independently trusted files.

| Artifact | Plain-language role | Startup agreement check |
|---|---|---|
| `request.json` | Test cover sheet: run, source, threshold, optional fault and plan identities | Exact schema; source/fault/threshold reconstruct the saved journal-plan digest |
| `evidence.json` | Portable record of what completed | Run ID and exact expected task graph match the cover sheet |
| `bindings.json` | Maps COM-LINK-001 to the Boolean check | Exact `COM-LINK-001 -> check` mapping |
| `report.json` | Authoritative engineering presentation contract | Reproduced from reopened evidence/bindings; verdict, source and threshold must agree |
| `report.html` | Human-readable view | Must exactly equal deterministic rendering of canonical report JSON |

The API uses bounded regular-file reads and rejects symbolic links. It reconstructs the
report without opening the execution journal/database and without receiving a task callback.
Only after every check passes does it create an immutable in-memory view and open the local
HTTP listener.

Example: suppose the cover sheet identifies source hash `A`, but the report claims its
link-margin details came from source hash `B`. Each file might be valid JSON in isolation,
yet the package cannot support one coherent engineering claim. Chimera refuses startup
instead of choosing one file or displaying a warning beside a possibly wrong PASS.

This is fail-closed consistency, not authenticity. SHA-256 identifies exact bytes but is
not a signature. Someone able to coherently replace every unsigned artifact on the trusted
local machine is outside the current prototype boundary. Authentication, TLS, remote use
and production hosting are not silently implied.

## 15–19 minutes — Practical exercise

Run the passing command above, then inspect the summary and report in a browser. Confirm:

- the same run ID appears in both JSON resources and the HTML report;
- the summary verdict agrees with COM-LINK-001 in the canonical report;
- `report_sha256` identifies the canonical JSON text (the saved file adds one transport
  newline); and
- the page says whether synthetic fault provenance is present.

Then stop the server with Ctrl+C, copy the run, change only its HTML and try to reopen it:

```bash
cp -R "$REVIEW_ROOT/pass" "$REVIEW_ROOT/tampered"
printf '\nchanged\n' >> "$REVIEW_ROOT/tampered/report.html"
chimera serve-link "$REVIEW_ROOT/tampered" --port 8765
```

Expected: exit 3 with `Saved HTML conflicts with canonical report`; no listener starts.
Delete the temporary review directories afterward. This demonstrates a consistency guard,
not malicious-host protection or digital-signature verification.
